# public/art/ — real, loaded game art assets

This directory holds real PNG (and, from Phase 74 onward, PNG+JSON atlas)
assets loaded through Phaser's normal texture pipeline, per the approved
visual overhaul plan at `docs/phase_73_to_78_visual_overhaul_plan.md`.

Everything here is served by Vite directly from `public/` (no build-time
processing), at `/art/<file>` in dev and copied verbatim into `dist/art/` on
`npm run build`.

Phase 76 raised `WILDLIFE_SPRITE_SIZE` (`src/config/wildlifeConfig.ts`) from
12px to **18px**, matching Phase 75's `ANIMAL_SPRITE_SIZE`/`RAIDER_SPRITE_SIZE`
bump (this constant was deliberately left at 12px in Phase 75, deferred to
Phase 76 since it's an independent literal, not an alias). Like
`ANIMAL_SPRITE_SIZE`, this is a texture-generation/loading size only -
wildlife sprites are placed centred and never `setDisplaySize`d. Real
AI-generated art for `wildlife-atlas.png` must be authored at 18x18, not the
old 12x12. `RAIDER_CAMP_SPRITE_SIZE` (24px) is unaffected by this change - it
is an independent literal, not part of the 12px small-unit size class.

**§5f note (raider-Coyote vs. wildlife-Coyote differentiation):** the plan's
§5f resolved that these two must be visually distinguishable even as
placeholders, so a future real-art pass has the pattern already established.
Both share the same base tan/brown color (`[0xbf, 0xa9, 0x80]`) so they still
read as "the same animal", but `raider-Coyotes` alone gets an extra horizontal
red bandana-stripe band near the top third of the frame - a placeholder stand-
in for the plan's real-art direction of giving the raid-faction Coyote a
bandana/scar marker. When real art replaces this atlas, replicate the same
concept (a bandana, scar, or similar hostile-marking accent on the raid
version only) rather than two identical Coyote sprites.

Phase 75 also raised the small-unit texture-generation size from 12px to
**18px** (`ANIMAL_SPRITE_SIZE` in `src/config/buildingConfig.ts`, and its
aliases `VILLAGER_SPRITE_SIZE`/`COWBOY_SPRITE_SIZE`/`BRAWLER_SPRITE_SIZE`/
`DYNAMITER_SPRITE_SIZE`/`RAIDER_SPRITE_SIZE`; `MOUNTED_COWBOY_SPRITE_WIDTH`/
`HEIGHT` scaled proportionally 16x12 → 24x18). This is a real, permanent
rendering-size change independent of the placeholder-vs-real-art distinction
above — real AI-generated art for these 6 atlases must be authored at 18x18
(24x18 for the mounted-cowboy frame), not the old 12x12/16x12.

## Why a placeholder

Phase 73 built the complete loading pipeline (folder structure, `BootScene`
load path, `gameConfig`'s `pixelArt: true`, the loading progress bar, and the
`tools/verify-asset-dimensions.mjs` dimension-check tool) but no
AI-image-generation tool was available in the environment that implemented
it. `tiles-atlas.png` is a functional stand-in only — correct file path,
correct dimensions, correct frame order/count — so the tilemap renders and
the pipeline can be proven end-to-end. It is **not** an attempt to replicate
the target art style described in the plan's §2 (hand-painted pixel art,
locked Western palette, top-left lighting, etc.).

## Before shipping this overhaul for real

Replace `tiles-atlas.png` with a real, AI-generated 160x32px, 5-frame strip
following the plan's §2 art direction spec and §3.4 generation pipeline, in
the exact same frame order (Dirt, Gravel, Sand, Water, Rock — this order is
load-bearing, see `src/config/mapConfig.ts`'s `TileType` enum and
`src/scenes/MainScene.ts`'s `map.addTilesetImage` call). After replacing the
file, re-run `node tools/verify-asset-dimensions.mjs` to confirm the new file
still matches the expected 160x32px before committing.

Replace `buildings-atlas.png` + `buildings-atlas.json` with real, AI-generated
art per the plan's §2 art direction spec (one building per `BuildingType`,
plus the 3 House-tier/WoodenGate variant frames), keeping every frame's exact
pixel dimensions (32x32 for a 1x1 footprint, 64x64 for a 2x2 footprint — see
`BUILDING_DEFINITIONS[type].size` in `src/config/buildingConfig.ts`) and exact
frame name (`buildingTextureKey()` in the same file is the source of truth —
do not rename frames). A hand-packed JSON atlas is fine to keep using (see
`tools/generate-placeholder-buildings.mjs` for the JSONHash shape Phaser 4's
`this.load.atlas()` expects), or repack with a real texture-packer tool if the
new art isn't laid out in one row. After replacing, re-run
`node tools/verify-asset-dimensions.mjs` (whole-file dimension sanity) AND
`node tools/verify-building-frames.mjs` (per-frame name + per-frame size
correctness against every `buildingTextureKey()` output) before committing.

Replace `animals-atlas.png`/`.json`, `cowboys-atlas.png`/`.json`,
`mounted-cowboys-atlas.png`/`.json`, `brawlers-atlas.png`/`.json`,
`dynamiters-atlas.png`/`.json`, and `villagers-atlas.png`/`.json` with real,
AI-generated art per the plan's §2 art direction spec, at exactly 18x18px
(24x18px for the mounted-cowboy frame — non-square, 4:3 ratio) and exactly
the frame names listed above (`animalTextureKey()`/`COWBOY_TEXTURE_KEY`/
`MOUNTED_COWBOY_TEXTURE_KEY`/`BRAWLER_TEXTURE_KEY`/`DYNAMITER_TEXTURE_KEY`/
`VILLAGER_TEXTURE_KEY` in `src/config/buildingConfig.ts` are the source of
truth — do not rename frames). §5b.1 of the plan applies here specifically:
these sprites are mirrored via `setFlipX` for facing, so author any
asymmetric identity cue (a holster, a lit fuse) either centred or duplicated
on both sides. After replacing, re-run `node tools/verify-asset-dimensions.mjs`
(whole-file dimension sanity) AND `node tools/verify-unit-frames.mjs`
(per-frame name + per-frame size correctness) before committing.

Replace `raiders-atlas.png`/`.json` and `wildlife-atlas.png`/`.json` with real,
AI-generated art per the plan's §2 art direction spec, at exactly 18x18px, and
exactly the frame names listed above (`raiderTextureKey()`/`wildlifeTextureKey()`
in `src/config/buildingConfig.ts`/`src/config/wildlifeConfig.ts` are the source
of truth — do not rename frames). Preserve the §5f Coyote differentiation
described above: `raider-Coyotes` must remain visually distinguishable from
`wildlife-Coyote` (bandana/scar or similar), not an identical reused sprite.
Replace `raider-camps-atlas.png`/`.json` with real, AI-generated art at exactly
24x24px per frame (`raiderCampTextureKey()` is the source of truth), preserving
the §5g per-faction differentiation (each camp should read as visually distinct
beyond just its tent-canvas color). After replacing any of these three, re-run
`node tools/verify-asset-dimensions.mjs` (whole-file dimension sanity) AND
`node tools/verify-raider-frames.mjs` (per-frame name + per-frame size
correctness) before committing.

Phases 77–78 will add further subdirectory-free atlas files here
(`vegetation-atlas.png`/`.json`, `carts-atlas.png`/`.json`,
`accents-atlas.png`/`.json`, `resource-icons-atlas.png`/`.json`) per the
